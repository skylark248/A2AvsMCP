## Critical Gaps

### B1 — `run_race()` Never Called from HTTP (BLOCKER)

No `POST /api/race/start` or equivalent HTTP endpoint in `web.py`. `run_race()` from `race/harness.py` is never imported or called outside the CLI `__main__` block and tests. `MANAGER.publish()` has no production caller. Result: opening `/race` accepts a WS connection but no race events are ever emitted — the page is permanently stuck in pre-race state.

**Fix required:** Add `POST /api/race/run` (or similar) endpoint in `web.py` that calls `run_race()` with `ws_emitter=MANAGER.publish` and assigns a `run_id` to return to the client, which then opens the WS with that `run_id`.

**Affected:** RACE-01..07, UIRACE-01..03, UIRACE-06, TRC-01..04

---

### B2 — WS `run_id` Param Mismatch (BLOCKER)

`/api/race/ws` declares `run_id: str = Query(...)` (FastAPI mandatory). `useRaceStream.ts:buildWsUrl()` constructs URL with only lane cursor params (`pure_mcp=N&pure_a2a=N&hybrid=N`). Every live connection attempt → HTTP 422 before WebSocket handshake. `raceReducer` immediately dispatches `ws_error`, sets `ws_status: "closed"`.

**Fix required:** Either (a) `useRaceStream` receives `run_id` from the start-race response and appends it to the WS URL, or (b) backend makes `run_id` optional for fresh connects (generates server-side).

**Affected:** TRC-04, UIRACE-01..03

---

### B3 — `heatmap_has_data` Hardcoded `false` (BLOCKER)

`RacePage.tsx:125`: `const heatmap_has_data = false` passed to `derivePageState()`. Phase 8 deferred this to Phase 9 (inline comment). Phase 9 wired `HardnessFailureHeatmap` correctly (fetches `/api/race/heatmap`, renders cells), but never fed that data back into `heatmap_has_data`. Page-state machine cannot reach `sparse-heatmap` state; heatmap footers render but `pageState` always ignores heatmap existence.

**Fix required:** Wire `useRaceHeatmap()` result into `heatmap_has_data` in `RacePage.tsx` (e.g. `const heatmap_has_data = !!heatmapData?.cells?.length`).

**Affected:** HEAT-01, HEAT-02, UIRACE-01
